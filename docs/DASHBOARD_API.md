# 대시보드(A) 연동 API

## `POST /api/dashboard/analyze`

질문 → 분석 계획 → 계산 엔진(C) → 로컬 Ollama 설명 → `{area, sql, text}`

요청

```json
{"question": "홍대의 음식점 분기별 매출을 보여줘."}
```

응답 200 (본문은 3개 필드로 고정)

```json
{
  "area": "hongdae",
  "sql": "",
  "text": "…계산 결과에 있는 수치로만 만든 설명…"
}
```

| 필드 | 규칙 |
|---|---|
| `area` | 지역 식별값. `성수 seongsu`, `홍대 hongdae`, `건대 geondae`, `강남 gangnam`, `이태원 itaewon` (`app/services/dataset.py`의 `AREA_IDS`) |
| `sql` | 계산 엔진이 `executed_sql`로 **실제 실행한 SQL을 보고했을 때만** 그 값. Pandas 계산이면 `""`. B는 SQL을 생성·실행하지 않음 |
| `text` | 계산 결과의 수치·근거만 사용. 아래 검증 참고 |

### Mock 표시 (실제 분석으로 오인 방지)
- 계산 결과가 Mock이면 `text`가 `[테스트용 Mock 데이터 기반 - 실제 분석 결과가 아닙니다]`로 시작하고, 응답 헤더 `X-Is-Mock: true`, `X-Data-Source: MOCK_TEST_DATA`가 붙는다.
- 본문 필드는 합의된 3개를 유지하기 위해 `is_mock` 필드를 추가하지 않았다. (협의 사항 참고)
- `APP_ENV=production`에서는 Mock 모드 자체가 503으로 차단된다.

### `text` 검증
1. 계산 결과에서 만든 사실 목록(FACTS)만 모델에 전달한다.
2. 모델 출력의 모든 숫자를 FACTS와 대조한다. FACTS에 없는 숫자(차이, 배수, 임의 수치)가 있으면 거부.
3. 순위·추천·예측 성격 표현(가장, 최고, 추천, 순위, 유망, 전망 등)이 있으면 거부.
4. 거부되면 한 번 재시도하고, 그래도 실패하면 모델 없이 계산 결과를 그대로 나열한 **결정적 템플릿 문장**으로 대체한다 (오류로 처리하지 않음).
5. 결과 행이 없으면 모델 호출 없이 "조건에 해당하는 계산 결과가 없습니다."를 반환한다.
- 한계: 숫자·금지어 외의 정성적 해석(예: "증가했습니다"의 방향 표현)은 자동 검증하지 않는다.

### 오류 응답 (`detail` 포함)
| 상태 | 상황 |
|---|---|
| 422 `needs_clarification` | 질문이 부족/미지원. `detail.clarification_question`, `missing_fields`, `reason` 제공. 이 경우 계산하지 않으며 본문은 분석 응답이 아님 |
| 422 `plan_validation_failed` | 계획이 데이터셋 규칙 위반 |
| 502 | 모델 출력 스키마 불일치 / 계산 엔진 응답 불일치 / 엔진이 `status=error` (`engine_error` 포함) |
| 503 | Ollama·계산 엔진 연결 불가, Mock 차단 |
| 504 | Ollama 또는 계산 엔진 시간 초과 |

## 합의가 필요한 사항 (A ↔ B)
1. **복수 지역**: 지역 비교 질문은 `area`를 하나로 못 정한다. 현재 임시안은 쉼표 연결(`"seongsu,hongdae"`), 지역이 없는 질문(업종 비교 등)은 `""`. 배열 또는 `areas` 필드 추가, 요청 시 A가 `area`를 지정하는 방식 등을 협의해야 한다.
2. **재질문 표현**: 현재 HTTP 422 + `detail`. A가 200 본문의 `text`로 받길 원하면 변경 가능(단, 분석 결과와 구분 필요).
3. **Mock 표시**: 헤더 + `text` 접두 방식. 본문에 `is_mock` 필드 추가 여부.
4. **지역 식별값 표기**: 특히 건대(`geondae`)와 A의 기존 식별값과의 일치.
5. 한 응답에 지표가 여러 개이거나 그룹이 많을 때 `text` 길이/형식.
